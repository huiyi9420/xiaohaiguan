## ① BusyBox df 超长设备名折行 → 固定列号取值全错（高危）

**现象**：设备 userdata 分区设备名 `/dev/block/bootdevice/by-name/userdata` 超长，BusyBox `df` 把该条目**折成两行**：第一行只有设备名，第二行才是数据（此时数据行没有设备名列）。`df -k /data | tail -n1 | awk '{print $4}'` 取到的"$4=Available"实际是 **Use%**（如 `"9%"` → `parseInt` → 9KB → 界面显示"磁盘剩余 0.0MB"）。

**真机实证**（2026-10-02，小海关 v2.1.4 诊断报告）：诊断报"磁盘剩余仅 0.0MB"，WebSSH 实测 `df -h /data` = 1.8G 总量 / 172M 已用 / **1.6G 可用 / 9% 使用**——纯误报。且 v2.1.5 新增的磁盘预检沿用旧口径，会把该形态设备**误判"存储不足"而拒绝启动引擎/拒绝下载内核**（宁可漏拦不可误拦的反面教材）。

**修法**（小海关 v2.1.6）：按挂载点匹配行、取倒数第三列，折行/不折行两种形态都对：

```sh
df -k /data /overlay 2>/dev/null | awk '$NF=="/data" || $NF=="/overlay" {print $(NF-2)}'
```

再加一层荒谬值滤除：<1MB 的读数物理不可能（跑得起插件的分区装得下内核+geo），视为解析残渣丢弃。JS 侧解析失败/空时返回 0 并让调用方"0=不拦截"。

**ET 自查点**：凡有 `df`+`awk '{print $N}'` 固定列号读磁盘/内存的地方（安装预检/诊断/日志）全部按此口径复核。

## ② 面板 showModal/closeModal 同一元素同 tick 先关后开 → 显窗被压制（高危）

**现象**：ZWRT 面板 `showModal`/`closeModal` 内部有关窗收尾（动画/延时清理）。同一个弹窗元素在同一 tick 内先 `closeModal('#x')` 再 `showModal('#x')`（典型场景：A 页面点按钮 → 关 A 弹窗 → 打开 B 进度窗，而 B 复用同一个 modal 容器），**紧随的显窗会被关窗收尾压制，窗口永远不出现**，流程转为全程后台隐形。

**真机实证**（2026-10-02，小海关 v2.1.4）：安装引导页点"在线下载"→ `mHide('hs_modal_simple'); onlineInstall()` → 进度窗（同一容器）从未显示，下载 6 分钟全程隐形，再点只弹"安装中"toast。

**修法**（小海关 v2.1.4）：
- 同容器换内容场景**不要先关再开**——直接换 `innerHTML` 再 `showModal`（或保持显示态只换内容）；
- "✕ 关闭不中断（转后台）"的设计必须配**回收入口**：busy 守卫命中时 `showModal` 切回进度窗，而不是只弹 toast；
- 后台流程的完成段操作进度窗 DOM 前必须判空（窗口可能已被用户关掉/内容被换掉，裸取 `.textContent` 会 TypeError 吞掉成功提示）。

**ET 自查点**：弹窗流转换处（安装进度/连接进度等复用同一 modal 的地方）grep `closeModal`/`mHide` 后紧跟 `showModal`/`mShow` 同 id 的调用链。

## ③ 复核校验与生成写入不对称 → 无接管/无规则路径升级死循环（高危）

**现象**：小海关升级复核要求三件套（fw.sh/start.sh/config.yaml）版本烙印齐备，但生成逻辑只在"挂接管"路径才写 fw.sh——**无接管模式的用户升级必然复核失败 → 自动回滚 → 对账再报待升级 → 再点再失败**，死循环。操作日志铁证：`升级复核未齐:F=0 S=2.1.4 Y=2.1.4`（S/Y 每次启动都被重写为新版，唯独 F 永不换新）。

**修法**（小海关 v2.1.5）：复核要求什么，**所有路径**就要写什么——无接管启动且检测到升级待办时，也 `writeFile(FW, genFwSh())` 只写盘不执行（零行为变化），烙印即齐。

**通用教训**：任何"生成器+复核器"设计（版本烙印/指纹/心跳），先列全生成器的**所有分支路径**，复核清单必须与每条路径的写入义务对称；否则被排除分支的用户会永久卡在复核失败。

**ET 自查点**：组件版本对账/升级复核逻辑（若有）——确认复核清单里的每个组件在所有启动模式下都有对应写入。

## ④ 设备外网 GitHub 空挂（连接建立但 0 字节停滞）

**现象**：设备侧 GitHub/SourceForge TCP 连接能建立但传输 0 字节停滞；ping 和 http 探测都会误报（ICMP 不转发 + 内网服务常仅 HTTPS）。验证连通性用 `curl -vk https://…`。

**已验证可用的国内源形态**（2026-10-02，小海关 v2.1.2-v2.1.3）：
- 网盘直链（`ufitools.ikuns.top`，需向商店申请，HTTP 200/206 可断点续传，~45KB/s）
- 自建 Gitee 镜像仓（`gitee.com/<owner>/<repo>` releases，API v5 查 latest，资产名**故意去掉 mihomo- 前缀防封**——ET 若镜像内核同理注意资产命名）
- `gh-proxy.com` 镜像前缀（唯一保留；ghfast.top/ghproxy.net 真机不稳已弃）

**ET 自查点**：内核/二进制下载链的源序列与版本查询兜底顺序。

## ⑤ 写盘失败静默（磁盘满/权限）一切"玄学不正常"的第一嫌疑

**现象**：满盘时 shell 重定向写文件**不报错**（`echo x > f` 静默失败），表现为配置保存"成功"但重启后丢、订阅更新无效、日志轮转失效——渐进式变坏，用户感知为"用一段时间就不正常"。诊断/预检必须读回校验（小海关 `writeFile` 以 `wc -c` 字节对账返回真假）。

**ET 自查点**：所有"写文件后不校验"的路径（配置/状态/自启行）；下载前空间预检记得用条目①的正确 df 口径。
